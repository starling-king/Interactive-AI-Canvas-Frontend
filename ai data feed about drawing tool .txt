### Requirements

### Edge Cases & AI Gotchas

* **Payload Collisions in Multiple Inputs:** `incomingJsonScope` merges upstream node payloads into a single flat object using `Object.assign` syntax (`{ ...scope, ...payload }`). If multiple source nodes emit the same variable key (e.g., `'out'`), the last one iterated silently overwrites earlier inputs with no handle-specific mapping (`left` vs `left-2`).
* **Circular Connection Loops:** Because upstream node changes immediately update `useNodesData`, creating a feedback loop (Node A $\rightarrow$ Node B $\rightarrow$ Node A) will trigger continuous debounced recalculations and updates, leading to canvas performance drops or infinite render cycles.
* **Non-Numeric or Divide-by-Zero Tooltip Crashes:** The right-handle output label executes `Number(prevOutRef.current[nodeVarName]).toFixed(2)`. If `MathEngine` returns a string, `NaN`, `null`, or complex object, the hover tooltip will display `NaN` or throw on invalid types.
* **Formula Auto-Assignment Pitfall:** If `data.formula` does not contain an `=`, the component automatically prepends `${nodeVarName} = `. If the input formula already assigns to another variable or contains syntax issues, `computedResults[nodeVarName]` might return `undefined`, causing the output value to fall back to `0`.
* **Asymmetric Global Metric Syncing:** The header button allows toggling `isGlobal` on `math` and `gate` nodes (since `hasInput1` is true), but the dispatch engine explicitly restricts writing to global metrics:
```javascript
if (isGlobal && (controlType === 'slider' || controlType === 'toggle'))

```


Consequently, `math` and `gate` nodes read from `globalMetrics` when toggled to Global, but will never write their computed results back into `globalMetrics`.
* **Wired Toggle Arbitrary Key Pick:** In `isWiredToggle`, the state evaluates `Object.values(incomingJsonScope)[0]`. If multiple variables arrive in `incomingJsonScope`, JavaScript object key enumeration order determines which upstream variable forces the toggle on or off.

### Combined Architecture: System Integration Dynamics

When deploying these 5 nodes (`InteractiveNode`, `ShapeNode`, `IconNode`, `TableNode`, `ContainerNode`, `TextNode`) and 4 edges (`KineticEdge`, `OrthogonalEdge`, `RelationalEdge`, `StraightEdge`) together as a unified system, several cross-cutting compatibility traps occur:

```
[InteractiveNode] --(outputValues.out)--> [Downstream Node]
        │
        └── (Top-level value/isActive NOT set on Toggle/Gate)
                    │
                    ▼
          [Smart Sensor in Edges] ---> Fails to trigger animation!

```

#### 1. Handle ID Inconsistency

* **Dual-Direction Refactored Nodes (`ShapeNode`, `TableNode`, `ContainerNode`):** Use explicit, unique handle IDs: `top-target`, `top-source`, `bottom-target`, `bottom-source`, `left-target`, `left-source`, `right-target`, `right-source`.


* **Strict Logic Node (`InteractiveNode`):** Uses strictly named directional IDs: `left`, `left-2`, and `right`.


* **Legacy Nodes (`IconNode`, `TextNode`):** Contain duplicate IDs for both source and target handles (`id="top"`, `id="bottom"`, etc.).


* **AI Action Item:** Never connect edges using a generic handle ID like `sourceHandle: "top"` across all nodes. An edge connecting from a `TableNode` to an `InteractiveNode` **must** specify `sourceHandle: "right-source"` (or `*-source`) and `targetHandle: "left"` or `"left-2"`. Connecting to `"right"` on `TableNode` will fail because that handle ID no longer exists.



#### 2. The Smart Sensor Activation Gap

* All four edge components use this hook to trigger visual animation:


```javascript
const isSourceActive = sourceNode?.data?.value === true || sourceNode?.data?.isActive === true;

```


* However, `InteractiveNode` dispatches data like this:


* **Toggle:** Saves to `data.defaultState` and `data.outputValues.out`, but **never** writes `data.value` or `data.isActive`.


* **Gate:** Saves to `data.outputValues.out` with boolean pass states, but **never** sets `data.value` or `data.isActive`.


* **Slider:** Sets `data.value`, but as a float/number (not a boolean `true`), meaning `=== true` evaluates to `false`.




* **Impact:** The Smart Sensor on all edges will remain inactive when connected to `InteractiveNode` unless `InteractiveNode`'s dispatch logic explicitly sets `isActive: Boolean(rawVal)` at the top level of `data`.



#### 3. State Desynchronization Across Custom Node Editors

* `ShapeNode`, `TableNode`, and `ContainerNode` buffer input locally with `useState` and lack reactive `useEffect` props watchers.


* `TextNode` does not call `updateNodeData` at all.


* **Impact:** If an AI flow builder programmatically updates edge configurations, labels, or node text via React Flow's store (`setNodes`), nodes with uncommitted or buffered local states will not synchronize with the incoming data until unmounted and remounted.



#### 4. Selection and Interaction Layering

* `ContainerNode` renders full-bleed hitboxes along its perimeter.


* `OrthogonalEdge` provides an expanded `interactionWidth={25}`, whereas `KineticEdge`, `RelationalEdge`, and `StraightEdge` rely on standard 2px click hitboxes.


* **Impact:** When edges are routed across or inside a `ContainerNode`, clicking to select an edge without `interactionWidth` will frequently trigger selection or dragging on the parent `ContainerNode` instead.

**MathEngine** is an expression parsing and evaluation utility that wraps `mathjs` to resolve mathematical assignments and boolean gate conditions by extracting variable identifiers and injecting zero-value fallbacks for missing scope variables.

### Requirements

* **Runtime Package Dependency:** Requires the `mathjs` npm package to provide the core `evaluate` function.


* **Consumer Integration:** Directly consumed by `InteractiveNode.jsx` to power `controlType === 'math'` (`processFormula`) and `controlType === 'gate'` (`evaluateCondition`).


* **Input Contracts:**
* `processFormula(formulaString, scope)`: Expects a formula string (e.g., `"output = a + b"` or a raw expression like `"a + b"`) and an optional key-value scope object (`incomingJsonScope` or `globalMetrics`).


* `evaluateCondition(conditionString, scope)`: Expects a conditional expression string (e.g., `"temperature > 100"`, `"status == true"`) and a scope object, returning a strict boolean.




* **Scope Structure:** Scope must be a flat JavaScript object mapping variable names to numerical or boolean values (e.g., `{ x: 10, y: 25 }`).



---

### Edge Cases & AI Gotchas

* **Built-in Function Shadowing & Scope Corruption:** `extractVariables` uses a regex (`/[a-zA-Z_][a-zA-Z0-9_]*/g`) to match variable names and only excludes a tiny list of built-ins: `['max', 'min', 'sum', 'abs', 'round', 'floor', 'ceil']`. If an AI or user writes standard math or trigonometric functions (e.g., `sin`, `cos`, `tan`, `sqrt`, `log`, `exp`, `pow`) or constants (`pi`, `e`), `extractVariables` treats them as missing variables and injects `0` into `safeScope`. When `mathjs.evaluate` runs, it tries to invoke `0(x)` or references `0`, triggering an immediate evaluation error and returning an empty result `{}`.


* **Logical Keyword Collision in Gates:** `extractVariables` does not filter out `mathjs` logical operators like `and`, `or`, `not`, or boolean literals `true` and `false`. Passing a condition like `"flowRate > 10 and status == true"` causes `and`, `status`, and `true` to be matched as variables. `buildSafeScope` sets `safeScope['and'] = 0` and `safeScope['true'] = 0`, corrupting the logical syntax and forcing `evaluateCondition` to fail and return `false`.


* **LHS Target Variable Zero-Injection:** `extractVariables` inspects the entire `formulaString` before separating target variable assignment. For a formula like `"speed = distance / time"`, `speed` is extracted alongside `distance` and `time`. If `speed` is undefined in `scope`, `safeScope['speed'] = 0` is injected into the scope. While harmless in simple one-way calculations, if a formula relies on an accumulator or recursive expression (e.g., `"count = count + 1"`), it will overwrite previous state and always evaluate to `0 + 1 = 1`.


* **Naive Assignment Split on Comparison Operators:** `processFormula` splits by `=` (`if (formulaString.includes('=')) { parts = formulaString.split('='); }`). If a formula uses comparison operators (e.g., `result = a == b` or ternary logic `result = (x >= 5 ? 1 : 0)`), splitting on the first `=` breaks the expression string or corrupts operator semantics.


* **Division-by-Zero via Injected Defaults:** Because missing inputs automatically default to `0`, formulas involving division (e.g., `"ratio = total / count"`) where upstream nodes are disconnected will calculate `total / 0`. In `mathjs`, division by zero evaluates to `Infinity`. This `Infinity` value flows into `InteractiveNode.jsx`, which attempts to serialize it into `outputValues.out` and render it via `.toFixed(2)` on hover, propagating non-finite numerical errors downstream.


* **Silent Error Swallowing:** All evaluation errors are caught via `try...catch` and logged exclusively via `console.warn`, returning `{}` for formulas and `false` for conditions. In `InteractiveNode`, an empty result defaults the node's output to `0` without notifying the UI or the user that a syntax error, unknown function, or parsing failure occurred.


* **Smart Sensor Disconnect with Flow Edges:** When `InteractiveNode` processes a gate or formula through `MathEngine`, it stores the computed result inside `data.outputValues.out = { [nodeVarName]: rawVal }`. However, your edge wires (`KineticEdge`, `OrthogonalEdge`, `RelationalEdge`, `StraightEdge`) check `sourceNode.data.value === true || sourceNode.data.isActive === true`. Because `InteractiveNode` does not write the evaluated gate or math result to `data.value` or `data.isActive`, animated flow wires plugged into `MathEngine`-driven nodes will remain completely inactive.

### Edge Cases & AI Gotchas

* **Double-Click Conflict (Inline Text vs. Inspector Panel):** `CanvasContent` binds `onNodeDoubleClick={handleNodeDoubleClick}` to open the floating `NodeInspector`. However, `ShapeNode`, `TableNode`, and `ContainerNode` also bind `onDoubleClick` directly to activate their inline `<textarea>` or `<input>` editors. When a user double-clicks any of these nodes to edit text, both the inline editor and the `NodeInspector` sidebar open simultaneously, causing UI clutter and conflicting focus states.


* **Hardcoded Edge Type Override:** The `handleNewConnection` callback intercepts all new wire drags and forces `type: 'edge_orthogonal'` with a hardcoded Slate `#94a3b8` closed arrowhead. Even if an edge connects two database tables (which should semantically use `RelationalEdge`) or links dynamic boolean logic (which uses `KineticEdge`), manual connections will always instantiate as `OrthogonalEdge` unless programmatically rewritten by an AI assistant or inspector dropdown.


* **Strict Connection Routing Failures:** The canvas enforces `connectionMode={ConnectionMode.Strict}`. In this mode, React Flow strictly forbids connecting source-to-source or target-to-target handles. While `ShapeNode`, `TableNode`, and `ContainerNode` define explicit `-target` and `-source` handles, `IconNode` and `TextNode` define identical handle IDs for both targets and sources (`id="top"`, `id="bottom"`, etc.). Under `ConnectionMode.Strict`, dropping a wire onto an `IconNode` or `TextNode` triggers ambiguity or snapping errors due to duplicate IDs.


* **Stale State in `NodeInspector`:** When double-clicking a node, `setActiveNode(node)` stores a snapshot of the node in local state. If that node’s data is subsequently mutated by background formula evaluations in `InteractiveNode`, by inline editing, or by an AI tool via the global Zustand store, `activeNode` does not update reactively. It holds stale snapshot data until the user closes and reopens the inspector.


* **Undo/Redo History Bypasses on Node Edits:** `takeSnapshot()` is called when dropping a node, adding from the panel, making a connection, and dragging a node (`onNodeDragStart`). However, node-internal updates—such as changing slider values in `InteractiveNode`, typing in `ShapeNode` or `ContainerNode`, and adding/deleting rows in `TableNode`—call `updateNodeData` directly without invoking `takeSnapshot()`. Consequently, inline textual and schema changes cannot be undone using `Ctrl+Z` / `Cmd+Z`.


* **Accidental Element Deletion on Defocused Inputs:** The keyboard shortcut listener protects `INPUT`, `TEXTAREA`, `SELECT`, and `isContentEditable` elements. However, if a user finishes typing inside a node and clicks away into the canvas pane, or clicks a button inside `NodeInspector` or `TableNode` without retaining input focus, pressing `Backspace` or `Delete` immediately calls `deleteSelectedElements()`, wiping the selected graph nodes without a confirmation prompt.


* **Silent Failure on Dropped Data:** In `handleDrop`, `JSON.parse` is wrapped in a defensive `try...catch` that falls back to `{}` if parsing fails. If external drop data contains malformed JSON or an unregistered `nodeType`, the node is either added with empty default data or will crash React Flow with an "unregistered node type" runtime error.


* **Infinite Skeleton Lockout on Fetch Errors:** `CanvasWorkspace` uses `lastWorkspaceId` ref to prevent repeated fetch calls, rendering `<SkeletonLoader type="canvas"/>` whenever `isFetching` is true. If `fetchCanvas` encounters an unhandled network error or server failure without flipping `isFetching` back to `false`, the workspace becomes permanently stuck on the loading skeleton screen.



**STRICT AI BANNED ACTIONS (The "Do Not Touch" List)**


* **Never update text or schema data globally without a remount:** Do not use `setNodes` to push new `data.label`, `data.title`, or `data.rows` to `ShapeNode`, `TableNode`, or `ContainerNode`. These components buffer state locally via `useState` without a `useEffect` watcher; AI-driven updates will trap stale data in the UI until the user remounts the node.


* **Never assign math/logic keywords blindly to `MathEngine`:** Do not generate formulas containing built-in math functions (`sin`, `cos`) or logical keywords (`and`, `or`, `true`). The engine's regex treats these as missing variables, injecting `0` into the `safeScope`, which instantly corrupts the logic and causes silent evaluation failures.


* **Never promise animated flows from `InteractiveNode` outputs:** Do not connect an `InteractiveNode` to a `KineticEdge` or `OrthogonalEdge` expecting animation. The edges listen for `sourceNode.data.value === true` or `data.isActive`, but `InteractiveNode` buries its evaluated gate and math results inside `data.outputValues.out`, leaving the wire's smart sensor dead.


* **Never use `data.label` for `TextNode`:** If dynamically generating a text node, exclusively bind the content to `data.text`. Using the standard `data.label` schema will cause the node to silently ignore the payload and default to "Type something...".



**SYSTEM-BREAKING EDGE CASES (What the AI Must Predict and Avoid)**

* **The Infinite Render Loop:** If the AI suggests or auto-generates a circular connection (Node A -> Node B -> Node A), the continuous debounced recalculations through `useNodesData` will trigger an infinite React render cycle, dropping canvas performance to zero.


* **Silent Payload Overwrites:** Because `incomingJsonScope` merges upstream data using `Object.assign`, if the AI routes two different nodes that both output the key `'out'` into a single target, the last processed node will silently overwrite the first with no handle-specific mapping.


* **The Division-by-Zero Tooltip Crash:** If the AI constructs a division formula (e.g., `ratio = total / count`) and the user has not yet connected the inputs, `MathEngine` injects `0` for the missing variables. This produces an `Infinity` result that flows to the `InteractiveNode` right-handle tooltip, crashing the `.toFixed(2)` renderer.


* **Data Loss on Defocused Deletion:** If the AI directs a user to type inside a `TableNode` or `NodeInspector` and the user clicks the canvas background without retaining input focus, hitting `Backspace` or `Delete` will immediately trigger `deleteSelectedElements()`, wiping out the node entirely without a confirmation prompt.


* **The Undo/Redo Blindspot:** The AI must recognize that `takeSnapshot()` is bypassed during inline text edits, slider movements, and table row updates. If the user makes a mistake inside a `TableNode` and hits `Ctrl+Z`, their schema changes will not revert.



**ENTREPRENEURIAL INSIGHTS & STRATEGIC LEVERAGE**

Applying lateral thinking to this architecture reveals that the root problem isn't the individual bugs—it is a fractured source of truth. Your React Flow global state and your local component states are fighting each other. From a business perspective, silent failures (like the `MathEngine` swallowing syntax errors and returning `0`, or the canvas permanently locking on `<SkeletonLoader/>` during a fetch error) are user-retention killers. Users will accept a tool that explicitly tells them they made an error, but they will immediately churn if their data silently vanishes or calculates incorrectly.

To apply Right Effort here, stop patching individual local state buffers. The highest ROI engineering move is to strip `useState` out of `ShapeNode`, `TableNode`, and `ContainerNode`. Force all keystrokes and row updates to dispatch directly to the React Flow global store via `updateNodeData`, debouncing the input if necessary for performance. This single architectural shift instantly solves your AI desynchronization, fixes the broken `Ctrl+Z` history, and ensures that when the AI touches the canvas, the UI actually updates.
